# Convex bindings snapshot

This folder is a byte-for-byte copy of `convex codegen` output — the same files
the Convex CLI writes to `src/convex/_generated/`. Nothing here is hand-written.

It exists so a static build host can build the app without Convex credentials or
a running `npx convex dev`. `src/convex/_generated/` is regenerated by the CLI,
so it is not something the app can rely on existing in a fresh checkout — but
both `tsc -b` (`src/convex/**` imports `./_generated/server`) and the browser
bundle (17 components import `@/convex/_generated/api`) require it.

`src/deploy/restore-convex-bindings.mjs` copies these files into
`src/convex/_generated/` when that folder is missing. It runs on `postinstall`
and at the start of `bun run build`, and it never overwrites an existing folder,
so local development is unaffected.

**Refresh after adding, renaming, or removing a Convex function:**

```bash
bun run convex:bindings:snapshot
```

That regenerates the bindings with the Convex CLI and re-copies them here. Run it
whenever `src/convex/*.ts` gains or loses a module, otherwise a fresh build will
typecheck against a stale `api.d.ts`.

These files are excluded from `tsconfig.app.json` on purpose: `api.d.ts` uses
paths like `../accounts.js`, which only resolve from inside `src/convex/`, so
typechecking them in place would report bogus "cannot find module" errors.
